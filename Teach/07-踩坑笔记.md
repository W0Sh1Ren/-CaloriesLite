## 坑 1 · `@Builder` 的参数只求值一次 ★最常见

### 现象

界面上有个值不更新。数据明明变了，界面显示的还是旧的。

### 例子

```ts
@Builder
optionRow(label: string, selected: boolean) { ... }

// 父组件里
this.optionRow('轻度活动', this.profile.activityLevel === level)
```

`this.profile.activityLevel` 后来变了，但 `optionRow` 里拿到的
**还是第一次构建时的值**。

### 原因

`@Builder` 的参数**只在容器构建时求值一次**，之后不会重新求值。
它不是函数调用，更像是「把值复制一份贴进去」。

### 解法

**方案 A：传函数（取值函数）**

```ts
@Builder
numRow(label: string, value: () => number) { ... }

// 调用时传箭头函数
this.numRow('年龄', () => this.profile.age)
```

`() => this.profile.age` 每次被调用时才去读，所以拿得到最新值。

**方案 B：改成 `@Component`**

```ts
@Component
export struct ProfileOption {
  @Prop selected: boolean = false;   // @Prop 会跟着父组件更新
}
```

### 本项目怎么选的

两种都用过。**结论：涉及交互（点击、选中态）的，一律用 `@Component`。**

因为这个坑在本项目里踩了**五次**：

| 踩在哪 | 表现 |
|---|---|
| 顶栏标题 | 切页面标题不变 |
| 热量环 | 数字变了环不重画 |
| 日历格子 | 记录状态变了不刷新 |
| 营养素条 | 数值不更新 |
| 「我的」选项卡片 | **点了没反应** |

最后一次（选项卡片）的教训最深：`@Builder` 的参数不仅值被冻结，
**连传进去的点击回调也被冻结了**，所以卡片「点不动」。
折腾了很久才发现是 `@Builder` 的问题。

> **判断方法**：如果一个组件的显示**依赖外部数据变化**、
> 或者**需要响应交互**，用 `@Component`。
> `@Builder` 只适合「纯粹的静态片段」，比如一段固定文案配图标。

## 坑 2 · `ForEach` 的 key 不包含变化的值

### 现象

列表里某一项的内容变了，但界面不更新。

### 例子

```ts
// ❌ key 只用下标
ForEach(this.cells, (cell: DayCell) => {
  this.dayCell(cell)
}, (cell: DayCell, i: number) => `${i}`)
```

日历上某天「从没记录变成有记录」，小圆点颜色应该变，
但界面不动 —— 因为 key 还是 `${i}`，框架认为「这一项没变」。

### 原因

框架靠 key 判断「哪一项是新的、哪一项只是内容改了」。
**key 相同 → 复用旧节点 → 不重新渲染**。

### 解法

**key 必须包含所有会变化的值**：

```ts
// ✅ 把状态编码进 key
}, (cell: DayCell, i: number) => `${i}-${cell.hasRecord}-${cell.deficit}`)
```

或者至少包含标识项：

```ts
}, (item: FoodRecord, i: number) => `${i}-${item.name}`)
```

### 一个更隐蔽的变体

本项目还遇到过这种：

```ts
// key 里带了「变体」但漏了一个维度
this.monthAnimKey = `${delta >= 0 ? 'n' : 'p'}${this.monthSeq}`
```

**这里的经验是**：如果「同一个触发信号要携带多种信息」
（比如「要播动画」+「往哪个方向」），
**把这些信息全部编码进 key 本身**，不要指望 `@Watch` 里再读别的字段。

因为 `@Watch` 回调里**读兄弟属性可能拿到的还是旧值**（同一帧内的时序问题）。

## 坑 3 · `@Builder` 调用不能链 `.onClick()`

### 现象

编译报错：

```
Property 'onClick' does not exist on type 'void'.
```

### 原因

`@Builder` 方法调用**返回 `void`**，不是组件对象，所以不能链式调用属性方法。

### 解法

**把 `@Builder` 调用包在一个容器里，事件绑在容器上**：

```ts
// ❌ 编译不过
this.kcalRing()
  .onClick(() => { ... })

// ✅ 包一层
Column() {
  this.kcalRing()
}
.width(84)
.onClick(() => { ... })
```

## 坑 4 · `@Link` 的父组件必须传「状态变量」

### 现象

编译**通过**，运行时**崩溃**：

```
SyntaxError: undefined 'expanded'[-61] <@Component 'MealFold'[36]>:
constructor: source variable in parent/ancestor @Component must be defined.
```

### 原因

```ts
// 子组件
@Link expanded: boolean;

// 父组件这样传 ❌
MealFold({ expanded: this.isExpanded(meal) })   // 传的是「方法返回值」
```

`@Link` 要求父组件传的是**一个状态变量的引用**，
不能是方法返回值、不能是表达式结果。

### 解法

| 需求 | 用什么 |
|---|---|
| 只需要「父变子跟着变」 | **`@Prop`**（单向，简单） |
| 需要「子也能改父」 | `@Link`，但父必须传 `$变量` |

**本项目最后改用了 `@Prop`** —— 因为折叠状态由父组件单向控制就够了，
不需要双向绑定。

> **教训**：`@Link` 是**运行时**才报错，编译期完全看不出来。
> 能不用就不用，`@Prop` 更安全。

## 坑 5 · `@StorageLink` 要求键「已存在」，否则冷启动崩溃

### 现象

加上 `@StorageLink('dataStamp')` 后，**App 启动即退出**。

### 原因

`@StorageLink` 在**绑定那一刻**就要求 `AppStorage` 里已经存在同名键。
而键是**第一次写数据时**才创建的，App 冷启动时还不存在 → 绑定失败 → 崩溃。

### 解法

**不要用 `@StorageLink` 做跨页通信**，改用静态回调（见第 5 章）：

```ts
// AppState.ets
static setDataListener(fn: () => void): void { ... }
static notifyDataChanged(): void { ... }
```

> 顺带一个限制：**同一个变量只能挂一个状态装饰器**，
> 所以也没法用 `@Watch` 去兜 `@StorageLink` 的问题。

## 坑 6 · `@Watch` 里改自己 → 无限递归爆栈

### 现象

```
RangeError: Stack overflow!
```

### 原因

```ts
@State @Watch('onTick') refreshTick: number = 0;

onTick(): void {
  this.reload();
}

private reload(): void {
  this.refreshTick++;    // ❌ 又改了自己 → 再次触发 onTick → 无限循环
}
```

### 解法

**约定：`reload()` 里绝不回写触发它的那个信号。**

本项目在代码里留了注释警告，并加了 `isReloading` 守卫兜底：

```ts
private reload(): void {
  if (this.isReloading) { return; }    // 重入守卫
  this.isReloading = true;
  try {
    // …真正的工作，绝不碰 refreshTick
  } finally {
    this.isReloading = false;
  }
}
```

> **通用建议**：写 `@Watch` 回调时，先想清楚
> 「我在这里改的东西，会不会又触发我自己」。

## 坑 7 · 用「条件渲染」做展开/收起 → 硬闪，没有动画

### 现象

想让一块内容展开时有动画，用了 `if`：

```ts
if (this.expanded) {
  Column() { /* 内容 */ }
}
```

结果高度**瞬间跳变**，加 `.animation()` 或 `animateTo` 都**没用**。

### 原因

条件渲染是「**有/无**」的切换，中间没有可插值的状态。
`animateTo` 需要「从数字 A 到数字 B」，而这里是「从无到有」。

### 解法

**始终挂载，只改高度**：

```ts
Column() {
  Column() { /* 内容 */ }     // ← 内容一直在，不删
}
.height(this.expanded ? TARGET_H : 0)   // ← 两端都是数字，可以插值
.clip(true)                              // ← 裁掉超出部分，视觉上「收起」
.opacity(this.expanded ? 1 : 0)          // ← 配合淡入淡出
```

外面再包 `animateTo`：

```ts
this.getUIContext().animateTo({ duration: 320, curve: Curve.EaseInOut }, () => {
  this.expanded = next;
});
```

**配合 `clip(true)`**，视觉上就是「内容被收起来了」。

> 本项目在**餐次折叠**、**个人情况展开**、**拍照页引导区收起**
> 三个地方都踩过这个坑，最后统一用这套写法。
> 详见 `docs\展开动画3.0.md`。

## 坑 8 · 用 `onAreaChange` 测量「高度受限容器」里的内容

### 现象

想自动测量内容高度，结果量到的是**容器被分配的高度**，不是内容的真实高度。

### 原因

`.onAreaChange` / `.onSizeChange` 报的是**容器被指定的尺寸**。
如果容器高度是我们自己设的（比如 420），那量到的永远是 420。

### 踩坑过程

这个坑导致「个人情况」里第 4 个选项**被裁掉**：

```
容器高度写死 420vp
内容实际需要 444vp
→ 第 4 项落在容器外，被 clip 掉
→ 但 onAreaChange 一直报 420，看起来「高度是对的」
```

### 解法

**算出来，不要测量**：

```ts
/* 明细区展开后的高度（vp）—— 按布局算出来的确定值
 *
 * 为什么不靠 onAreaChange 测量：这个组件的外层就是靠 detailsH 定高的，
 * 内层在「高度已知的容器」里布局，量到的往往是容器值而不是内容高度。
 * 明细内容是固定的（不是变长的列表），所以直接算最稳。
 */
const DETAILS_H: number = 452;
```

算法就是**把每一块的高度加起来**：

```
性别行      36
三个数值行  45 × 3 = 135
间距        14 × 4 = 56
分隔线      1
两列区      标题16 + 间距6 + 44×4 + 6×3 = 216
            ─────────
            444  ⇒ 取 452 留余量
```

### 同样的问题也发生在餐次折叠

`components\MealFold.ets` 里：

```ts
const RECORD_ROW_H = 72;   // 实测出来的单条高度

export function mealDetailHeight(count: number): number {
  return count <= 0
    ? DETAIL_PAD_TOP + EMPTY_HINT_H + EMPTY_BOTTOM_EXTRA
    : DETAIL_PAD_TOP + DETAIL_PAD_BOTTOM + count * RECORD_ROW_H + (count - 1) * DETAIL_GAP;
}
```

**注意 `RECORD_ROW_H = 72` 是实测值**，不是估的。
注释里写明了：**如果改了 `RecordRow` 的样式，这个常量必须重新测量**。

> ⚠️ 还有一个相关坑：**`.shadow()` 不占布局空间**。
> 早期算高度时把阴影也加进去了，结果多算了几个 vp。

## 坑 9 · `layoutWeight` 是「按比例分配剩余空间」

### 现象

想让中部区域变高，怎么改都不动。

### 原因

```ts
// 中部
.layoutWeight(1)
// 底部
.layoutWeight(1) 和 .layoutWeight(2)
```

`layoutWeight` 的含义是「**按比例平分剩余空间**」，
**不是「占多少高度」**。

两处都用，剩余空间就被两家分掉了，谁也多不了。

### 解法

**只让一方吃掉剩余空间**：

```ts
// 中部：唯一吃剩余空间的
.layoutWeight(1)

// 底部按钮行：删掉 layoutWeight，让它就是按钮的高度
// （不写 layoutWeight，容器就按内容自然高度）
```

> **另一个相关坑**：`layoutWeight(1)` 在 `Column` 父容器里
> 表示**垂直**方向扩展，在 `Row` 里表示**水平**方向。
> 搞混了会得到完全相反的效果。

## 坑 10 · Canvas 不在属性动画通道里

### 现象

用 `animateTo` 包住状态变更，然后手动 `draw()`，弧线**直接瞬移**到终值。

### 原因

`animateTo` 只插值**属性**（宽高、位置、透明度……）。
Canvas 上的弧线是**一次性画上去的路径**，不在属性系统里，
回调里拿到的永远是**最终值**。

### 解法

**自己按帧推进**（`common\Theme.ets` 的 `ValueTicker`）：

```ts
this.timer = setInterval(() => {
  const elapsed = Date.now() - this.startedAt;
  const t = Math.min(1, elapsed / this.duration);
  const eased = 1 - Math.pow(1 - t, 3);       // easeOutCubic
  this.current = this.from + (this.to_ - this.from) * eased;
  apply(this.current);
  if (t >= 1) { this.stop(); }
}, 16);
```

**别忘了 `stop()`**，否则组件销毁后定时器还在跑。

## 坑 12 · 卡片 UI 里做派生计算 → 读不到值 ★隐蔽

### 现象

卡片上进度条按 0 渲染、文字为空，**而且不报错**。

### 原因

**卡片进程的响应式追踪不追踪 getter / 辅助方法内部对 `@LocalStorageProp` 的依赖。**

```ts
// ❌ 在卡片里，这些都读不到数据
this.macroBar('蛋白', this.protein, this.proteinTarget)   // 方法内读属性
private isEmptyDay(): boolean { return this.intake <= 0; } // 方法内读属性
get primaryText() { ... }                                  // getter
```

它只认「在 `build()` 里**直接**读属性」。

### 解法

**卡片 UI 零派生** —— 所有计算在**后端**（`widget\CardData.ets`）做完，
卡片只负责把字符串贴上去。

```ts
// 后端算好，作为 payload 推过来
proteinPct: string = '0%';
proteinText: string = '0 / 188 g';

// 卡片直接用
Text(this.proteinText)
```

### 怎么判断自己踩了

**改卡片时如果发现想「顺手算一下」，那就该往 `CardData` 里加字段了。**

## 坑 15 · `preferences` 的框架级进程内缓存 ★最折磨

### 现象

App 里记完一笔，桌面卡片点「刷新」**没反应**；
但**过一阵再点**，或者等很久，数值又对了。

### 排查过程（数据说话）

```
一次记录后连续 7 次刷新 → records=7  intake=1880   ← 全是旧值
过了一会儿（进程重启）  → records=9  intake=2280   ← 新值
```

**唯一的关键线索**：**进程号（pid）变了**。

### 原因

`preferences` 在**框架层**还维护一份**进程内缓存**，
而且它**不会因为别的进程写了新值就失效**。

卡片进程是长驻的 → 读到的永远是**启动那一刻的快照**。
「过一阵自己好了」其实是系统**把卡片进程回收重启**了。

### 走过的弯路

**第一版修法**（无效）：

```ts
Store.prefs = null;        // ❌ 只丢掉了「我们这一层」的引用
Store.init(context);       //    框架那层的缓存还在
```

日志显示 `hadCache=true ready=true` —— 「重新打开了」，
**但读回来还是旧值**。

**正确修法**：

```ts
Store.prefs = null;
// ↓ 关键：把实例从【框架缓存】中移除，之后才会真的重新读文件
preferences.removePreferencesFromCacheSync(context, STORE_NAME);
Store.init(context);
```

### 教训

> **跨进程共享的存储，在长驻进程里必须假设它有缓存。**
> 而且要查到**框架层**，不只是自己的引用。
>
> 排查这类问题的关键线索是：**进程有没有重启过**。
> 如果「重启就好」，那就是缓存问题。

## 坑 16 · `.gitignore` 会静默吞掉你的文件

### 现象

`git add docs/图标原图.png` **没有任何报错**，但提交里就是没有这个文件。

### 原因

`.gitignore` 里有一条 `/docs/*.png`（本来是挡调试截图的），
把项目资产也一起忽略了。

### 解法

**用 `-f` 强制加入**：

```powershell
git add -f docs/图标原图.png
```

**并且在提交前核对文件清单**：

```powershell
git show --stat --oneline HEAD
```

### 教训

> `git add` **不会告诉你「这个文件被忽略了」**，它是静默失败的。
>
> 提交后一定要**看一眼文件清单**，确认想提交的都在里面。
> 特别是图片、二进制这类文件容易被 ignore 规则误伤。

## 坑 17 · ArkTS 严格模式的几个「莫名其妙」

### 现象与解法

| 报错 | 原因 | 解法 |
|---|---|---|
| `'animateTo' can't support form application` | 卡片环境不支持 | 卡片里不做动画 |
| `Property 'onClick' does not exist on type 'void'` | `@Builder` 返回 void | 包一层容器 |
| `Module '"@kit.ArkUI"' has no exported member 'focusControl'` | `focusControl` 是**全局命名空间**，不是模块导出 | 不要 import，直接用 |
| `No overload matches this call` | 方法有多个重载，传字面量时匹配错了 | 声明成显式类型的变量再传 |
| `Property 'X' does not exist on type 'Y'` | 该 API 在你这个 **API 版本**上不存在 | 查 SDK 定义确认，别信网上的答案 |
| `Property 'RESIZE' does not exist on type 'typeof KeyboardAvoidMode'` | 枚举需要 import | `import { KeyboardAvoidMode } from '@kit.ArkUI'` |
| 结构相同但类型不兼容 | ArkTS 不支持**结构化类型** | 显式构造目标类型的对象 |
| 不能用 `any` / `unknown` | `arkts-no-any-unknown` 规则 | 用具体类型 + 类型断言 |

### 查 API 的正确姿势

**不要只信搜索结果**（可能是旧版本的）。查你本机 SDK 里的定义文件：

```
D:\DevEco26\DevEco Studio\sdk\default\openharmony\ets\
├── api\            ← 能力接口定义（.d.ts）
└── component\      ← UI 组件定义（.d.ts）
```

比如想确认 `TextInput` 有没有某个属性：

```powershell
Select-String -Path '...\component\text_input.d.ts' -Pattern 'showKeyboardOnFocus'
```

**没有输出 = 这个 API 在你的版本上不存在**，得换方案。

## 坑 18 · 「固定底栏」会压住内容

### 现象

把操作按钮放进页面底部的固定栏（不在滚动区里），
结果**底栏压住了上面的输入框**。

### 原因

「固定」的含义就是「脱离文档流」。
底栏固定在容器底部，就会**覆盖**滚动内容。

### 踩坑过程（一个我自己引入的回归）

| 版本 | 做法 | 结果 |
|---|---|---|
| 1.4 | 按钮在滚动区底部 | 被键盘挡住 |
| 1.5 | 挪进**固定底栏** | **底栏压住输入框** ← 我引入的新问题 |
| 1.5.1 | 回归自然流 + 收起大块引导区 | ✅ |

### 教训

> 修一个布局问题时，**先想「这个改法会不会挡住别人」**。
> 「固定定位」的固有代价就是会覆盖内容。

**更好的思路**：与其让按钮「固定」，不如**让内容变短**。
本项目最后的解法是「输入时把那块 180vp 的空状态引导区收起来」，
输入框和按钮就自然浮上来了 —— **不是把按钮钉住，而是给内容腾地方。**

## 坑 19 · 键盘避让：默认只压扁窗口，不重排版

### 现象

键盘弹起时，底部按钮**被挡住**。

### 排查（量数据）

```
点输入框后：窗口  2832 → 1733   （系统确实避让了）
           按钮  y=2670         （仍在键盘后面）
```

**结论**：窗口被压扁了，但**页面内部没有重新排版**。

### 原因

ArkUI 默认的键盘避让模式是 `KeyboardAvoidMode.OFFSET`
（把页面整体上移），不是 `RESIZE`（按新高度重新排版）。
页面用固定底栏时，OFFSET 会把底栏一起推出可视区。

### 解法

```ts
this.getUIContext().setKeyboardAvoidMode(KeyboardAvoidMode.RESIZE);
```

离开页面时记得还原成 `OFFSET`（这是**页级**的全局设置，
不改回去会影响其它页面）。

**改后**：按钮从 y=2670 变成 y=1571，稳定落在键盘上方。

## 坑 20 · 焦点会「自己跑掉」

### 现象

在聊天框点「发送」后，焦点跑到了另一个输入框（菜品克重栏）。

### 原因

```ts
this.revising = true;   // ← 这会让输入框 .enabled(false)
```

**被禁用的 `TextInput` 会丢失焦点**，框架随即把焦点交给下一个可用输入框。

### 解法（三处配合）

```ts
// ① 不要禁用输入框 —— 重复提交由守卫拦住
if (text.length === 0 || this.revising) { return; }

// ② 程序化聚焦时不弹键盘
.enableKeyboardOnFocus(false)

// ③ 把焦点钉回去
focusControl.requestFocus('chatInput');
inputMethod.getController().stopInputSession();
```

### 关于「收键盘」的时机

```ts
// ❌ 错的：等模型回复才收键盘（要等几秒，期间键盘一直挡着）
await VisionService.revise(...);
this.hideKeyboard();

// ✅ 对的：点发送的瞬间就收
this.hideKeyboard();
await VisionService.revise(...);
```

## 坑 21 · `postCardAction` 的事件格式不统一

### 现象

`onFormEvent(formId, message)` 收到的 `message` 是个字符串，
但**不同资料里说的 JSON 结构不一样**：

```
'{"action":"message","params":{"action":"start"}}'   ← 完整对象
'{"action":"start"}'                                  ← 只有动作
'start'                                               ← 纯字符串
```

### 解法

**防御式解析**，三种都认：

```ts
private static parseAction(message: string): string {
  if (!message) { return ''; }
  try {
    const obj = JSON.parse(message) as Record<string, Object>;
    // 优先取 params.action
    const paramsObj = obj['params'];
    if (paramsObj) {
      const inner = paramsObj as Record<string, Object>;
      const a = inner['action'];
      if (typeof a === 'string' && a.length > 0) { return a; }
    }
    // 兜底取顶层 action，但要排除 'message' 本身（那是事件类型，不是业务动作）
    const top = obj['action'];
    if (typeof top === 'string' && top !== 'message' && top.length > 0) { return top; }
    return '';
  } catch (e) {
    return message;   // 不是合法 JSON，可能就是纯动作字符串
  }
}
```

> **遇到「格式不确定」的输入，写一个容错解析函数，比赌一种格式可靠。**

## 坑 22 · 时间精度不够，导致「数据没变」的误判

### 现象

同一分钟内连点两次刷新，第二次**界面不动**。

### 原因

刷新时间戳格式化成了 `"14:36 更新"`（只到分钟）。
同一个分钟内，这个字符串**没变化**，
绑定数据被判定为「没变化」而不重绘。

### 解法

**格式化到秒**：`"14:36:05 更新"`。

> 这个坑比较特殊，但思路通用：
> **如果某个值被用作「有变化就刷新」的信号，
> 它的精度必须足够区分每一次变化。**

## 坑 23 · 别在两个地方写同一份「默认值」

### 现象

卡片刚加出来时**闪一下**——先显示一组数字，然后跳到另一组。

### 原因

卡片在「绑定数据到位前」会先按声明初值渲染一帧。
如果**卡片里的初值**和**后端兜底值**不一致，那一帧就会和最终值不同。

### 解法

**让两边用同一份来源**：

```ts
// CardData.ets 里定义一次
static readonly DEFAULT_BUDGET: number = 2000;

// 卡片声明初值时引用它，而不是写死 2000
@LocalStorageProp('budget') budget: number = CardData.DEFAULT_BUDGET;
```

**更进一步**：干脆用一个「兜底数据」函数同时供两处使用：

```ts
private static readonly FALLBACK: CardData = CardData.fallback();
@State ringAnim: number = CalorieCard.FALLBACK.kcalRingRatio;
```

> **通用原则**：同一个值在多处出现 = 迟早不一致。
> 抽成一个常量或一个函数，一处定义、多处引用。

## 坑 24 · 并行跑构建会互相踩

### 现象

```
Hvigor config file D:\CaloriesApp\tools\proj\hvigor\hvigor-config.json5 does not exist
```

构建突然失败，之前明明好好的。

### 原因

同时跑了**两个构建**。两个进程都在重写 `tools\proj` 这个临时副本，
互相把对方的文件删了。

### 解法

**永远不要并行跑两个构建。**

> 这个坑在自动化流程里特别容易踩：一个后台任务还没结束，
> 又启动了第二个。**启动构建前先确认上一个已经结束。**

## 坑 25 · 用 PowerShell 改源码会毁掉中文

### 现象

用 PowerShell 脚本处理 `.ets` 文件后，**所有中文变成乱码**
（`瑙嗚夊父閲?` 这种）。

### 原因

PowerShell 的默认编码和文件实际的 UTF-8 编码不匹配。

### 解法

**只用专门的编辑工具改源码**（DevEco Studio、VS Code 等），
不要用 PowerShell 的 `Set-Content` / `Out-File` 去重写源码文件。

如果必须用脚本，要显式指定 UTF-8 且不带 BOM：

```python
with open(path, 'w', encoding='utf-8') as f:
    f.write(content)
```

> 附带一个排查提示：**用 PowerShell 的 `Get-Content` 看中文源码，
> 显示乱码不代表文件坏了**（可能只是终端编码问题）。
> 用编辑工具打开确认。
