# 01 · 认识鸿蒙 App

这一章不谈代码，先把「App 到底是什么」讲清楚。
**跳过这章直接看代码，后面很多设计你会觉得莫名其妙。**

---

## 一、App 就是一堆文件 + 一个运行环境

你手机上每一个 App，本质上都是一个**压缩包**，里面装着：

```
代码文件      ← 界面长什么样、点了按钮干什么
图片资源      ← 图标、背景图
配置文件      ← 叫什么名字、需要什么权限、有几个页面
签名信息      ← 证明「这个包是我做的，没被人改过」
```

这个压缩包在鸿蒙里叫 **HAP**（Harmony Ability Package），
在安卓里叫 **APK**。它们的关系就像 `.zip` 和 `.rar`——格式不同，作用一样。

**关键点**：App 不是「网页」。网页是运行在浏览器里的，
而 App 是**直接跑在操作系统上**的，所以能调用摄像头、能读写文件、能常驻后台。
代价是必须**针对每个操作系统单独开发**——这就是为什么有安卓版、iOS 版、鸿蒙版。

---

## 二、鸿蒙和安卓、iOS 是什么关系

三个**互相独立**的手机操作系统：

| | 鸿蒙 HarmonyOS | 安卓 Android | iOS |
|---|---|---|---|
| 谁做的 | 华为 | 谷歌 | 苹果 |
| 开发语言 | **ArkTS** | Kotlin / Java | Swift |
| 开发工具 | **DevEco Studio** | Android Studio | Xcode |
| 打包格式 | **HAP** | APK | IPA |

它们**不通用**。给安卓写的 App 不能直接装在鸿蒙上，反之亦然。
所以「做一个 App」这句话，实际含义是「**针对某一个系统**做一个 App」。

本项目做的是**鸿蒙版**。

---

## 三、版本号：为什么到处看到 API 26

鸿蒙的版本有两套编号，容易混：

| 名称 | 例子 | 含义 |
|---|---|---|
| **系统版本** | HarmonyOS 7 | 用户在「设置」里看到的版本 |
| **API 版本** | API 26 | **开发者**用的编号，代表「能用哪些功能」 |

**API 版本才是开发时要关心的。** 因为：

- 系统版本 7 对应的就是 API 26
- 每个 API 版本会**新增**一些能力，也会**废弃**一些
- 你的代码声明「我要 API 26」，系统就不让你用 API 27 才有的功能（这是好事，能提前发现兼容问题）

本项目目标：**HarmonyOS 7 / API 26**，实机测试设备是华为 Mate 80。

> **踩坑记录**：不同 API 版本 API 差异很大。本项目在 API 26 上就遇到
> 「`TextInput` 没有某个属性」「某个方法签名不一样」这类问题，
> 网上搜到的答案可能是旧版本的，**要以你 SDK 里的实际定义为准**（后面讲怎么查）。

## 四、一个 App 装到手机上，中间发生了什么

这是新手最容易懵的地方，我用流水线的方式讲：

```
① 你写的代码              一堆 .ets 文件（文本）
        ↓  编译
② 中间代码                变成机器能更快读懂的格式
        ↓  打包
③ 未签名的 HAP            还是个压缩包，但系统不认
        ↓  签名
④ 已签名的 HAP            ← 用你的证书盖了个章
        ↓  安装
⑤ 出现在手机桌面          系统验证签名，通过就装上
```

### 为什么要「签名」

想象你收到一个陌生 App，怎么知道它没被人塞进病毒？

**签名**就是答案：开发者用一个只有自己有的「私钥」给包盖章。
系统用对应的「公钥」验证——**改过任何一个字节，验证就会失败**。

所以签名有两层作用：

1. **证明来源**：这个包确实是某个开发者发的
2. **保证完整**：内容没被篡改过

### 调试签名 vs 正式签名

| | 调试签名 | 正式签名 |
|---|---|---|
| 用在哪 | 自己手机测试 | 上架华为应用市场 |
| 怎么来 | DevEco Studio 自动生成（需登录华为开发者账号） | 在华为开发者后台申请 |
| 能装几台 | 通常只限你注册的设备 | 不限 |

本项目用的是**调试签名**——因为只给自己用。

> **本项目的实际情况**：`build-profile.json5` 里预留了签名配置的引用，
> 但证书本身在你本机（DevEco Studio 里生成），**证书文件不会提交到 Git**
>（那属于敏感文件）。所以你换一台电脑 clone 下来，需要重新生成一次签名。

## 五、鸿蒙 App 的「Ability」是什么

鸿蒙里有个核心概念叫 **Ability**，可以理解成「**App 对外的一个入口**」。

一个 App 可以有多个 Ability，各干各的：

| 类型 | 作用 | 本项目的例子 |
|---|---|---|
| **UIAbility** | 有界面的入口，「一个页面窗口」 | `EntryAbility` —— App 的主入口 |
| **FormExtensionAbility** | 桌面卡片的后台服务 | `CalorieCardAbility` —— 那个 2×2 的桌面卡片 |

**为什么桌面卡片要单独一个 Ability？**

因为桌面卡片**不在你的 App 里运行**。它由系统的「卡片框架」托管，
即使你的 App 没打开、甚至被系统杀掉了，卡片还得显示在桌面上。

这是一个很重要的设计约束，后面第 6 章讲卡片时会详细说它的后果。

## 六、开发工具：DevEco Studio

华为官方的鸿蒙开发工具，**免费**，基于 JetBrains 的 IntelliJ 平台做的
（所以界面和 Android Studio、WebStorm 很像）。

它帮你做这些事：

| 功能 | 说明 |
|---|---|
| **代码编辑** | 语法高亮、自动补全、报错提示 |
| **预览** | 改完界面能立刻看到效果，不用每次都装机 |
| **编译打包** | 一键把代码变成 HAP |
| **签名** | 自动生成调试证书 |
| **装机调试** | 连上手机直接运行，能看日志 |

**新手建议**：先用图形界面。本项目的 `tools/` 下有一堆命令行脚本，
那是为了在**受限环境**里构建才写的，正常用 DevEco Studio **不需要**它们。

## 七、这个项目的「性格」

最后说说设计取向，这决定了代码为什么这样写。

**目标**：极简。

- 只做三件事，**不做**会员、广告、社交、打卡任务
- 没有账号系统 —— 不需要登录
- 数据只存本机 —— 不上传、不同步

**这些选择直接影响了代码**：

| 决定 | 代码上的后果 |
|---|---|
| 不做账号 | 不需要网络请求库、不需要登录态管理 |
| 数据只存本机 | 用本地键值存储（`preferences`）就够，不需要数据库 |
| AI 用用户自己的 Key | 不需要后端服务器，App 直连 AI 服务商 |
| 极简 | 页面少（4 个），组件复用度高 |

> 一个项目的代码长什么样，**很大程度上是被产品决策决定的**，
> 不只是技术选择。看懂这点，你就不会觉得「为什么不做个更完整的功能」——
> 那是**故意不做**的。

---

## 小结

- App = 压缩包（鸿蒙叫 HAP）+ 运行环境，不是网页
- 鸿蒙 / 安卓 / iOS 三套独立体系，本项目是鸿蒙
- **API 版本**（不是系统版本）才是开发时要看的
- 代码 → 编译 → 打包 → **签名** → 安装，签名保证来源和完整性
- **Ability** 是 App 对外的入口，桌面卡片是单独一种 Ability
- 产品上的「极简」直接决定了代码的简单
