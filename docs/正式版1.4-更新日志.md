# 正式版 1.4 · 更新日志

**上一版**：正式版 1.3
**定型提交**：见本文件所在提交

```bash
git checkout 正式版1.4     # 或 release-v1.4
```

本版把「记录」从**必须有照片**改成**文字也行**，并在识别结果页加了
**和模型对话、实时调整热量**的能力；另外重排了「个人情况」的布局。

## 新增

### 一、纯文字也能记录

原来拍照页必须至少有一张照片才能提交；现在**有照片或有描述，任一即可**。

- 输入框标题由「补充说明」改为「吃了什么」，占位文案说明「不拍照也能记」
- 主按钮文案随状态变：有照片是「开始识别」，纯文字是「估算热量」
- 走独立的文字提示词（`TEXT_SYSTEM_PROMPT`），要点是：
  **信息不足时按最常见的做法与份量给出合理估算**，不要因为描述简略就返回空；
  且**用户说的量词要当真**（「半碗」就是半碗，不按一整份算）

### 二、和模型对话，实时调整热量

识别结果页明细下方新增对话面板。用户可以对结果做增量修正：

```
和模型聊聊                    可以改，也可以直接加
                    ┌──────────────┐
                    │ 其实是两碗    │   ← 用户：靠右，浅绿底
                    └──────────────┘
┌────────────────────────────┐
│ 牛肉面由一碗改为两碗，      │       ← 模型：靠左，浅灰底
│ 克重与营养值整体翻倍。      │
└────────────────────────────┘
[ 例如：米饭其实是两碗    ] [发送]
```

- 「米饭其实是两碗」→ 该条按比例重算，**热量合计当帧刷新**
- 「还喝了一碗汤」→ 新增条目
- 「这个不要了」→ 删除条目
- 只是提问（「这个热量对吗」）→ 条目不变，给出回答
- **条目删光后仍可继续聊**（「再加一碗米饭」），从零加回来

实现要点：把**当前明细作为 JSON 上下文**发给模型，要求「只改提到的地方，
其余原样保留」——这样用户已经手动改过的字段不会被重新识别冲掉。

### 三、发送后立刻收起键盘

点发送时（**在发请求之前**）取消焦点并结束输入会话：

```ts
focusControl.requestFocus(null);                    // 取消焦点
inputMethod.getController().stopInputSession();     // 收键盘
```

放在 `await` 之后是错的：模型要几秒才回，那期间键盘一直挡着界面。

### 四、拍照页键盘不再挡住主按钮

监听键盘高度，在滚动区底部补一段等高空白，把「估算热量」顶到键盘上方。
注意回调给的是 **px**，布局用 **vp**，要除以屏幕密度（本机 3.5）。

## 改动

### 个人情况：日常活动量 | 减脂目标 改为左右两列

原来两组各占满整行、上下堆叠，8 个选项叠起来很高，「目标」被顶到屏幕外
（用户反馈「显示不全，缺少减脂目标」）。摊成两列后总高度减半，一屏看全。

- 单个选项**固定高度** `OPTION_ROW_H`：两列并排时左右描述行数不同，
  不固定会高矮不一
- 展开高度改成**按布局算出的常量**（`DETAILS_H`），不再用 `onAreaChange` 测量：
  这个容器自身就是靠它定高的，内层在「高度已知的容器」里布局，
  `onAreaChange` 往往把容器值报回来（420 被反复量回 420，
  第四项「增重增肌」因此落在容器外被裁掉）
- 活动量由 5 档减为 **4 档**（去掉 `VERY_ACTIVE`），与目标列数量对齐

### 选项卡片改用 @Component

`ProfileOption` 从页面里的 `@Builder` 抽成独立组件。

**原因**：`@Builder` 的参数只在容器构建时求值一次，`selected` 状态与
点击回调都会被**冻结**——表现是「卡片点不动」。做成 `@Component` 后
`@Prop` 的更新会驱动重建，事件也能直接绑在组件根节点上。

## 数据兼容

`VERY_ACTIVE` 从**界面选项**里去掉，但**保留在 `ACTIVITY_ORDER` 里**
（反序列化校验用），否则老档案里存着该值的用户会被重置成默认档。

读取时把它收敛到 `ACTIVE`（语义最接近），避免出现「四项都没选中」的观感。
