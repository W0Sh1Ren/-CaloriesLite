**上一版**：正式版 1.1.1

本版修掉了一个**数据记错地方**的真 bug（补记日期），并把补记入口
从手动输入改成拍照识别；另外补上了详情卡片的日期滑动手势。

## 修复

### 补记永远记到当天（数据 bug）

**现象**：在记录页翻到任意一天点「补记」，不管选的是哪天，
记录都会落到**今天**；完成后首页也跳到今天。

**原因**：`ResultConfirm.confirm()` 里写死了 `todayKey()`：

```ts
const day: string = todayKey();   // ← 忽略了用户选中的日期
```

同时 `Index.onPageShow()` 与 `switchTo()` 也各自把 `dayKey` 重置成
`todayKey()`，所以即使数据记对了，界面也回不到那一天。

**修复**：新增 `AppState.targetDay` 作为「本次记录要记到哪一天」的载体：

| 环节 | 行为 |
|---|---|
| 记录页 / 详情页点补记 | 写入 `AppState.targetDay = 选中日期`，再进拍照页 |
| 确认页保存 | 用 `AppState.effectiveTargetDay()`（空串等价今天）落库 |
| 返回首页 | `onPageShow` / `switchTo` 读同一来源，停在补记的那一天 |
| 用户放弃（相机页直接返回） | `aboutToDisappear` 里清空，不影响下一次 |

`targetDay` 在首页读完后**故意不清空** —— `onPageShow` 与 `switchTo`
可能先后触发，先清的话第二次就退回今天了。

## 改动

### 补记改为拍照识别（原来跳手动输入页）

记录页与详情页的补记入口由 `pages/ManualAdd` 改为 `pages/Camera`，
复用「拍照 → 识别 → 确认」这条链路。

**顺带满足了一个隐含需求**：确认页本来就能选餐次，所以
「有记录的日期也能补记，并按餐次插到对应位置」自然成立。

补记时相机页的默认餐次改为读 `AppState.targetMeal`，
不再只用「当前几点」去猜 —— 补记场景下「现在几点」没有意义。

### 只有今天才显示悬浮「拍照识别热量」

翻到历史日期时该按钮隐藏。

理由：那个按钮的语义是「现在拍一张」，必然记到今天；
与正在浏览的日期不一致，容易误操作。历史日期要补记，
走记录页的补记入口（那里会把日期带上）。

### 详情卡片支持左右滑切换日期

记录页第二个卡片（当日详情）新增 `PanGesture`：

- 左滑看后一天、右滑看前一天，与日历翻月方向一致
- 阈值 40vp，与日历换月保持一致（两个卡片相邻，手感要统一）
- 滑到别的月份时**日历跟着切过去**，否则高亮的日期不在当前显示的月里
- 未来日期拦截，提示「已经是最新一天了」

## 未改动

`pages/ManualAdd`（手动添加页）**保留但已无入口**。
留着不影响功能，代价是多一份维护成本；是否删除待定。

## 验证

四条改动均经真机验证通过：

1. 记录页选一天补记 → 数据落到那一天、完成后首页停在那一天
2. 翻到历史日期 → 悬浮拍照按钮消失
3. 详情卡片左右滑 → 正常切日期，滑到今天之后再滑有提示
4. 有记录的日期补记 → 选「晚餐」后插到晚餐那一栏
