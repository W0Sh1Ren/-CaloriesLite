# 正式版 1.5 · 更新日志

**上一版**：正式版 1.4
**定型提交**：见本文件所在提交

```bash
git checkout 正式版1.5     # 或 release-v1.5
```

本版集中解决**输入法与焦点**两个交互问题：键盘遮挡底部按钮、
发送消息后焦点跑到别的输入框。

---

## 修复

### 一、键盘不再挡住底部按钮

**现象**：拍照页第一次点「吃了什么」输入时，输入法把「估算热量」按钮盖住。

**排查过程**（实测数据，不是猜的）：

1. 点输入框后量窗口：`root y=[140,2832]` → `[140,1733]`，
   说明系统**确实做了键盘避让**，窗口被压扁了 1099px；
2. 但同一时刻「估算热量」按钮的坐标仍是 **y=2670** ——
   落在键盘（从 1733 开始）后面；
3. 也就是说：**窗口被压扁了，页面内部却没有重新排版**。

**根因**：ArkUI 默认的键盘避让模式是 `KeyboardAvoidMode.OFFSET`
（把页面整体上移），不是 `RESIZE`（按新高度重新排版）。
页面用固定底栏时，OFFSET 会把底栏一并推出可视区。

**修法**：这两个页面显式改成 `RESIZE`：

```ts
this.getUIContext().setKeyboardAvoidMode(KeyboardAvoidMode.RESIZE);
```

改后同一个场景：

| | OFFSET（默认） | RESIZE（现在） |
|---|---|---|
| 窗口高度 | 2832 → 1733 | 2832 → 1733 |
| 估算热量按钮 | **y=2670（键盘后）** | **y=1571（键盘上方）** |

离开页面时还原成 `OFFSET`，避免影响其它页面
（避让模式是页级的全局设置）。

**顺带**：拍照页的「拍照 / 相册」与主按钮一起移入固定底栏，
输入时不用滚动就能点到。

> 曾经尝试过「监听键盘高度、在滚动区补一段等高空白」的做法，**已废弃**：
> 那是绕路，真正的原因是避让模式不对。相关代码已删除。

### 二、发送消息后焦点保持在聊天输入框

**现象**：在结果页点发送后，焦点跑到菜品的**克重输入框**上。

**根因**：`this.revising = true` 会让聊天输入框 `.enabled(false)`，
而**被禁用的 TextInput 会丢失焦点**，框架随即把焦点交给下一个可用输入框。

**修法**（三处配合）：

1. **不再禁用输入框** —— 重复提交由 `ask()` 开头的 `this.revising` 守卫拦住，
   不需要禁用控件；
2. 输入框设 `enableKeyboardOnFocus(false)` ——
   程序化聚焦不弹键盘，所以「钉焦点」不会把刚收起的键盘又弹起来
   （用户手指点击仍会正常弹键盘）；
3. `focusControl.requestFocus(chatInputId)` 把焦点钉回聊天框，
   发送前调用一次，模型返回、明细重建后再调用一次
   （明细整体替换会重建页面，可能再次挪走焦点）。

## 验证

- 拍照页点输入框：按钮完整露在键盘上方
- 结果页发送消息：模型返回后焦点仍在聊天输入框，直接接着打字不会打进菜名
- 对话调整功能正常（实测把牛排从 1 份改成 3 份，热量按比例重算）

## 排查方法上的记录

本版两个问题都是**先量数据、再改代码**解决的：

- 用 `uitest dumpLayout` 读节点的 `bounds`，对比键盘弹起前后的坐标；
- dump 里每个节点都带 `focused` 属性，可以直接读出「焦点在谁身上」，
  不必靠肉眼判断。

这两点比截图可靠 —— 截图只能看到静态结果，证明不了事件链路和焦点归属。
