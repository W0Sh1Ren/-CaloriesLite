## 修复

### 日历翻到非本月，点进去返回后被拉回本月

**现象**：在记录页翻到上个月（或更早），点某一天进详情，返回后日历**跳回当前月**，
而不是停在点进去之前的那个月。

**原因**：`HistoryTab.onRefreshTick()` 里无条件地把日历视口同步到主页面的日期：

```ts
if (this.dayKey.length > 0) {
  this.selectedDay = this.dayKey;
  const d = new Date(fromDayKey(this.dayKey));
  this.viewYear = d.getFullYear();      // ← 视口被拉回 dayKey 所在月
  this.viewMonth0 = d.getMonth();
}
```

而**从二级页返回时 Index 会 `refreshTick++`**，这段就跟着跑了一遍。

原来用 `this.selectedDay !== this.dayKey` 当守卫，但这个条件在用户
自行翻月点选日期后**恰好为真**（用户在 9 月点了 9/15，而 `dayKey` 还是 10/4），
所以守卫形同虚设——真正该判断的是「主页面日期有没有变」。

**修复**：新增 `lastSyncedDay` 记录上一次同步过来的主页面日期，
只在**它真的变了**时才动日历视口：

```ts
private syncToMainDay(): void {
  if (this.dayKey.length === 0 || this.dayKey === this.lastSyncedDay) {
    return;                                // 只是子页面返回触发的刷新，不动视口
  }
  this.lastSyncedDay = this.dayKey;
  this.selectedDay = this.dayKey;
  const d = new Date(fromDayKey(this.dayKey));
  this.viewYear = d.getFullYear();
  this.viewMonth0 = d.getMonth();
}
```

`onRefreshTick()` 与 `onDidUpdate()` 都改走这一个方法，避免两处逻辑再次分叉。

## 两类触发的区分（本次的关键）

`refreshTick` 会被两类事件触发，处理方式**必须不同**：

| 触发源 | `dayKey` | 该做什么 |
|---|---|---|
| 主页面翻了日期 | **变了** | 日历跟过去（选中日 + 视口月份） |
| 从二级页返回 / 别处写了记录 | 没变 | **只重读数据，不动视口** |

之前把两者当成一回事，才出现「翻到 9 月、点进去返回、被拉回 10 月」。
