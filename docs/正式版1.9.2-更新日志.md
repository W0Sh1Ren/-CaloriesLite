## 一、热量缺口三档配色 ★

### 原来的问题

首页的环只有两态：达标绿 / 超标红。而「实际缺口」和「计划缺口」的关系
有三档，中间那一档（没超出消耗、但没跟上计划）原来是绿的，看不出落后。

### 新规则

| 条件 | 颜色 | 环心文案 |
|---|---|---|
| 实际缺口 **≥** 计划缺口 | 🟢 绿 | 缺口 |
| **0 ≤** 实际 **<** 计划 | 🟡 黄 | 未达标 |
| 实际 **< 0**（超出总消耗） | 🔴 红 | 超出 |

**分档基准是「计划缺口」而不是 0**，这一点很关键：

> `计划缺口 = TDEE − 每日目标`，它本身就是「想减的那部分」。
> 按计划吃到目标那天，实际缺口正好等于计划缺口 —— 那是**达标**，
> 不该因为「没有额外少吃」就变黄。
> 只有吃得比目标还多（实际 < 计划）才算没跟上。

边界已验证：

```
缺口 1200 → 🟢      缺口 300 → 🟢   ← 正好吃到目标，达标
缺口  299 → 🟡      缺口   0 → 🟡   ← 没超消耗但落后于计划
缺口   -1 → 🔴      缺口 -500 → 🔴  ← 能量盈余
```

退化情况也对：维持目标（计划缺口 = 0）、增重目标（计划缺口 < 0）
时，只要不超出总消耗就是绿。

### 桌面卡片同步修好

卡片原来把环色**写死成绿色**（`.color(COLOR_PRIMARY)`），所以超标不变红。
现在环色由后端算好推过来：

```ts
// CalorieCard
.color(this.ringColor)
```

卡片 UI 跑在系统渲染进程且要求**零派生**（响应式追踪不认 getter / 运算），
所以颜色和三行文案全部在 `CardData.fillDerived()` 里算完，卡片只贴值。

可用日志排查：

```
card deficit: actual=942 planned=300 -> 缺口 ringColor=#22C55E
```

### 环心内容与首页对齐

卡片环心改成与首页同一套三行结构：**标签 / 缺口数字 / 千卡**。

> 环的**进度条**画的是「已摄入 / 每日目标」（吃掉了多少），
> 环心的**数字**是「缺口」。两者方向相反但是同一件事的两面：
> 吃得越多，进度条越满、缺口越小。

## 二、本月缺口补上脂肪换算

记录页「本月缺口」下面加一行小字：

```
本月缺口 -94 千卡
相当于 -12 g 脂肪
```

系数走 `KCAL_PER_KG_FAT`（7700 千卡/kg → 7.7 千卡/g），
并新增共享函数 `kcalToFatGrams()`，界面不再自己算。

### 顺带统一了一处重复定义

`CalorieCalc.estimateDaysToGoal()` 原来直接写了字面量 `7700`，
而 `Theme.ets` 里已有 `KCAL_PER_KG_FAT` —— 同一个物理量两处定义。
现在改为引用常量，只剩一个来源。

## 三、悬浮拍照按钮：收起 / 展开动画

### 问题

按钮只在「今天」显示，原来是 `if` 条件渲染 —— 节点整体出现或消失，
**没有任何中间帧**，观感是硬切。

### 做法

改为**常挂载 + scaleX 收缩**：

```ts
.scale({ x: this.cameraBarOn ? 1 : 0, y: this.cameraBarOn ? 1 : 0 })
.opacity(this.cameraBarOn ? 1 : 0)
.animation({ duration: 600, curve: curves.cubicBezierCurve(0.34, 1.56, 0.64, 1) })
```

| 选择 | 理由 |
|---|---|
| **scaleX 而不是 width** | 改 `width` 会**重新排版**整棵子树，每帧一次，廉价设备会掉帧；`scale` 不参与布局，只在合成阶段压扁，代价几乎为零 |
| **`scaleY` 也要给 0** | 只缩 X 不缩 Y，按钮会变成一根竖线 |
| **回弹曲线** | 第二控制点 y = `1.56` > 1，会**冲过目标再回落**。展开时冲到略大于 1（弹一下），收起时压过头再回一点 —— 这就是 Q 弹的来源 |

**Q 弹程度的调法**（`cubicBezierCurve` 的第二个 y）：

```
1.0  不弹，平滑收缩
1.3  轻微
1.56 当前
2.0  很夸张
```

> 时长与回弹要一起调：`duration` 压到 200ms 以下，
> 回弹看不出来（来不及展示「冲过头」和「弹回来」两拍）。

### 收起后必须让出点击

`scaleX=0` 时按钮仍占着那条横带，不处理会出现
「点空白处却跳去拍照」：

```ts
.enabled(this.cameraBarOn)
.hitTestBehavior(this.cameraBarOn ? HitTestMode.Default : HitTestMode.None)
```

### 状态同步抽成单一入口

`dayKey`（数据）与 `cameraBarOn`（它的动画化表现）必须永远一致，
而 `dayKey` 有三四个写入点。新增 `setDayKey()` 把所有写入点收拢，
避免以后加东西时漏掉一处、出现「历史日期上还浮着拍照按钮」。
