# 展开动画 2.0

折叠面板动效的第二版。**在首页四个餐次（早餐/午餐/晚餐/加餐）上定型。**
与 [展开动画 1.0](展开动画1.0.md) 的差别只有一条，但很关键。

---

## 一、与 1.0 的唯一差别：状态按实例分开

| | 展开动画 1.0 | 展开动画 2.0 |
|---|---|---|
| 高度状态 | 一个标量，所有面板共用 | `Map<key, number>`，每个面板各自一份 |
| 透明度状态 | 一个标量，共用 | `Map<key, number>`，各自一份 |
| 适用场景 | 页面上**只有一个**可折叠面板 | 页面上有**多个**可折叠面板 |

动效定义本身完全一致（透明度插值 + 高度即时变化 + animateTo），见下节。

---

## 二、为什么共用状态会坏（1.0 用在多面板时的四个 bug）

1.0 里只有一份 `bodyH` / `alpha`。页面上有四个餐次时：

| # | 现象 | 原因 |
|---|---|---|
| 1 | 展开没记录的卡片时，卡片**突然跳到别的长度再展开** | 展开前要把高度重置成占位值，而占位值属于**所有**卡片，当前卡片按错误的起点起跳 |
| 2 | 折叠 B 时，**A 的内容变空白** | 折叠 B 走 `animateTo`，同一帧里共享的 `bodyH` 也变了，A 随之被裁到 B 的高度 |
| 3 | 同时展开多张，**切换日期后新卡片也展开且长度沿用上一张** | 长度是共享的，谁最后量谁说了算 |
| 4 | 有 6 道菜时**只显示 5 道，第 5 道还被裁掉一点** | 占位值 `MEAL_BODY_PLACEHOLDER_H = 400` 不够高，量到的自然高度被容器限制，改写回高度时就偏小 |

**第 4 条的机制值得单独记**：内层是在一个固定高度的裁切容器里被布局的，
所以 `onAreaChange` 量到的「自然高度」在超出容器时会被**截断**。
量到偏小的值再写回去，长度就永远不够 —— 内容被裁在固定长度上。

因此占位值不能当成最终高度用，也不能指望它「够大就行」；
正确做法是**让每张卡片各自量、各自记**，并且量到的值只影响它自己。

## 三、动效定义（与 1.0 相同）

```ts
private toggle(key: K): void {
  const next: boolean = !this.isExpanded(key);
  if (next) {
    this.setH(key, PLACEHOLDER_H);        // 先恢复占位，逼它重新量
  }
  this.getUIContext().animateTo({ duration: DUR_MEAL_EXPAND, curve: Curve.EaseInOut }, () => {
    this.setExpanded(key, next);          // 高度：即时变化
    this.setAlpha(key, next ? 1 : 0);     // 透明度：动效来自这里
  });
}
```

容器：

```ts
Column() { if (isExpanded(key)) { /* 明细内容 */ } }
  .width('100%')
  .height(isExpanded(key) ? this.h(key) : 0)
  .clip(true)
  .opacity(isExpanded(key) ? this.alpha(key) : 0)
```

明细内容自己挂 `.onAreaChange` 回报自然高度。

**测量只认展开中的那一个**：收起态卡片高度是 0，内层虽然仍会被布局
（这是能测到高度的关键技巧），但那时量到的值不可信，写进去会污染下次展开的起点。

## 四、为什么不用高度动画（与 1.0 相同的结论，仍然成立）

试过三种写法，**都没有中间帧**：

| 写法 | 结果 |
|---|---|
| 容器挂 `.animation()`，靠 `height` 变化插值 | 没有中间帧 |
| `animateTo` 里只改展开状态，高度靠 `height()` 响应 | 没有中间帧 |
| 两阶段（先测高度、下一帧再动画） | 仍然没有中间帧 |

**根因**：`.height()` 从「占位值」跳到「实测值」的那一帧跨过了不可插值的边界。

所以高度交给即时变化，动效交给透明度。
⚠️ 不要把 `.opacity()` 换成 `.animation()`，也不要删掉 alpha 状态。

---

## 五、不要用 `transition` 做折叠（同 1.0）

给「会因条件为假而卸载」的节点挂 `transition`，条件转假时节点立刻从树上移除，
动画跑在一个不参与布局的元素上，会**与下方控件重叠**。
