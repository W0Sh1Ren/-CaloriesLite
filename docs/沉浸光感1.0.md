## 一、视觉构成

### 1.1 顶部毛玻璃（自绘，覆盖式）

`:entry/src/main/ets/components/GlassTopBar.ets`

```
Stack({ alignContent: Alignment.Top })     ← 页面根
├─ 底层  Column → 当前页内容（各页自己用 topReserve() 留白）
└─ 顶层  GlassTopBar .zIndex(1) .hitTestBehavior(Transparent)
```

| 项 | 值 |
|---|---|
| 底色 | `#B3FFFFFF` |
| 模糊 | `backdropBlur(24)` |
| 安全区 | `AppState.topInset`（EntryAbility 用 `getWindowAvoidArea` 实测） |
| 本体高度 | `TOP_BAR_BODY = 62vp` |
| 底缘 | `shadow({ radius: 12, color: 'rgba(0,0,0,0.03)', offsetY: 4 })` |

**关键**：内容层**不能**加 `padding({ top: topInset })`。顶栏是覆盖层，内容必须能在滚动时从顶栏**下面穿过去**被模糊掉——如果内容整体下移，就永远滚不到顶栏底下。

## 三、踩过的坑（改之前先看这里）

### 坑 1：导航栏整体左偏 51px

**现象**：92% 宽的胶囊贴在屏幕左边，左空 0px、右空 102px。

**根因**：页面根 `Stack` 用了 `alignContent: Alignment.TopStart`（**左**对齐）。

**解法**：改 `Alignment.Top`（水平居中）。

### 坑 2：玻璃发灰，像灰色塑料板

**根因**：`backgroundBlurStyle` 会按 `BlurStyle` 档位**一并调整亮度与饱和度**，在浅色页面上把整条压暗一档。

**解法**：改用 `backdropBlur(radius)`——它**只做背景模糊**，亮度完全由底色决定。

### 坑 3：`blurRadius` 编译不过

`backgroundBlurStyle` 的第二个参数是 `BackgroundBlurStyleOptions`，字段**只有**：

```
colorMode / adaptiveColor / scale / blurOptions / policy / inactiveColor
```

`blurRadius` 是**前景 `blur()`** 的入参。模糊强度只能选 `BlurStyle` 档位。

### 坑 4：`build()` 里不能有副作用

`draw()` 放进 `build()` 会报 `build method can have only one root node`。Canvas 动画只能靠外部定时器逐帧驱动。

### 坑 5：`ForEach` 键与数值无关 → 子组件被复用

键写成 `${index}-${label}` 时，ArkUI 会**复用子组件并跳过重建**，数字永远停在首帧。必须把每帧递增的 `frame` 编进键里。

### 坑 6：`layoutWeight(1)` 在 `Column` 父级 = 纵向扩张

MacroBar 的 `Stack` 曾被撑到整张卡片高。横向布局要用 `Row` 包一层。

## 四、已知边界：官方沉浸材质在本工程不生效

`getMaterialInfo().state` 恒为 0，`systemMaterial` 怎么配都不渲染。

参考 [WeiboPura《新 API26 沉浸光感经验汇总》](https://github.com/haohaoai0/WeiboPura/blob/main/docs/%E6%96%B0API26%E6%B2%89%E6%B5%B8%E5%85%89%E6%84%9F%E7%BB%8F%E9%AA%8C%E6%B1%87%E6%80%BB.md) §1.1：

> **真沉浸材质只在官方白名单槽位渲染；白名单之外的一切点位，只能靠 `backgroundBlurStyle` 真模糊磨砂。**

| 档位 | 生效范围 |
|---|---|
| **A 档** 弹窗类 / 按钮与选择类 | 页面内**任意区域** |
| **B 档** 其他组件（含布局容器） | **仅限** `Navigation` 标题栏 与 `Tabs(barPosition:End)` 底部 TabBar |

「页面 body 里的**自绘浮层 / 吸顶叠层**」被明确标为 ❌ **out of scope**。

**本工程的顶栏和自绘底部导航都属禁区**——所以用模糊兜底不是退而求其次，是唯一可行路径。

### 想吃官方材质的唯一路径

把顶栏搬进 `Navigation` 的 `title` 槽位（该文档 §6.10 真机已验证）：

```
Navigation() { Content() }
  .title({ builder: this.TitleBar(), height: 108 },
         { barStyle: BarStyle.STACK, backgroundColor: Color.Transparent })
  .mode(NavigationMode.Stack)
  .hideTitleBar(false)
  .hideBackButton(true)
  .expandSafeArea([SafeAreaType.SYSTEM], [SafeAreaEdge.TOP, SafeAreaEdge.BOTTOM])
```

槽内子元素各自挂 `.systemMaterial(...)`。

**代价**：
- 页面根多一层 `Navigation` 壳，参与手势分发与返回键处理
- 观感必然从「半透明 + 描边 + 轻投影」变成**系统玻璃**
- 底部导航**没有对应槽位**（只能走 `Tabs(barPosition:End)`，得把自绘结构整个换掉）

## 五、其他参考结论

该文档另给出几条本工程适用的口径：

- `lightEffect: null` 才是**禁用**流光；传 `{color: undefined}` 等于显式启用（会在栏上沿出现一条亮线）
- `applyShadow: true` 会把材质阴影投到浅色卡面上，合并成「一层淡阴影」
- 底色**必须带透明度**，不透明色会完全遮挡材质滤镜
- `hitTestBehavior` 挂不到系统内部节点上——自建 `Tabs` 空壳开全宽时会吞掉下层列表的滚动，只能靠收窄几何解决
