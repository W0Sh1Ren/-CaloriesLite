## 修复

### 确认记录无法回到首页

**现象**：拍照识别 → 确认识别结果 → 点「确认记录」后，回到的是**拍照页**，
还要再按两次返回才能回首页。

**原因**：照片识别的页面栈是 `[Index, Camera, ResultConfirm]`，
而确认时只调用了一次 `router.back()`，只退一层，落到 Camera 上。

**修复**：拍照页跳确认页由 `pushUrl` 改为 `replaceUrl`。

```
页面栈：[Index, Camera, ResultConfirm]
   ↓ replaceUrl
        [Index, ResultConfirm]
```

于是确认时一次普通的 `back()` 就落到首页。

选这个改法而不是「想办法退两层」，是因为**拍照页在拍完之后本来就没有留在栈里的意义**——
用户不会想「返回照片选择」。替换掉它在语义上也是更正确的，
顺带让「退两层」这个需求根本不存在。

## 排查记录（三个无效写法，避免重走）

这一版在同一个问题上试错了三次，都是「想办法一次退两层」这个方向：

| 写法 | 结果 |
|---|---|
| `router.back()` | 退一层 → 落到拍照页（原始 bug） |
| `router.back(2)` | `index` 语义不是「退几层」，**实测无效** |
| `router.back({ url: 'pages/Index' })` | 文档写明「目标 URL 不在栈里时不执行任何操作」，入口页入栈 URL 没有把握 |
| `router.back({ url: '/' })` | `'/'` 不是真实页面 URL，**同样匹配不到 → 哪都不跳** |

**教训**：`RouterOptions.url` 文档里那句「`'/'` 表示首页」指的是**跳转**语义
（`pushUrl` / `replaceUrl`），不是「返回栈中已存在的首页」。
`back(options)` 的语义始终是「回到栈里已存在的某个页面」。

最终有效的是 `replaceUrl` —— 改的是**栈的构成**，而不是**返回的方式**。

## 未改动（有意保留）

点确认页顶部的返回键（`‹`）**仍然回到拍照页**，因为那是「我要改照片」的语义，
与「确认记录后回首页」是两件事。
