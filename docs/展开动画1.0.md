# 展开动画 1.0

折叠面板的展开/收起动效规范。**在「我的 → 个人情况」上定型，用户确认「非常好」。**
新做折叠面板请直接套用，不要再另发明一套。

---

## 一、动效定义

用 `animateTo` 显式驱动，**动效由透明度承担，高度即时变化**：

```ts
private togglePanel(): void {
  const next: boolean = !this.expanded;
  if (next) {
    this.panelH = PANEL_PLACEHOLDER_H;   // 展开前恢复占位高度，逼它重新量
  }
  this.getUIContext().animateTo({ duration: DUR_MEAL_EXPAND, curve: Curve.EaseInOut }, () => {
    this.expanded = next;               // 高度：即时变化（保证布局与占位正确）
    this.alpha = next ? 1 : 0;          // 透明度：这一条才是那个「动效」
  });
}
```

容器：

```ts
Column() {
  if (this.expanded) {
    Column() { /* 明细内容 */ }
      .width('100%')
      .onAreaChange((o: Area, n: Area) => { this.onPanelArea(n); })  // 量自然高度
  }
}
.width('100%')
.height(this.expanded ? this.panelH : 0)
.clip(true)
.opacity(this.alpha)      // ← 动效来源，不要删
```

参数：`duration = DUR_MEAL_EXPAND (320ms)`，`curve = Curve.EaseInOut`。
箭头旋转用**同一个 duration**，两者才是一体的。

视图观感：内容**浮现/隐去**，而不是「突然出现」。高度同步变化，占位不残留。

## 二、为什么不用高度动画（试过很多次，都不成立）

想做成「高度从 0 撑到 h」，试过三种写法，**都没有中间帧，观感是硬闪**：

| 写法 | 结果 |
|---|---|
| 容器挂 `.animation()`，靠 `height` 变化插值 | 没有中间帧 |
| `animateTo` 里只改 `expanded`，高度靠 `height()` 响应 | 没有中间帧 |
| 两阶段（先测高度、下一帧再动画） | 仍然没有中间帧 |

**根因**：`.height()` 从「占位值」跳到「实测值」的那一帧跨过了**不可插值的边界**
（一端是未设置/占位，另一端是量出来的真实值），插值器拿不到有效的起点。

所以结论是：**高度交给即时变化，动效交给透明度。**
高度变化本身必须保留（否则占位不释放、会与下方控件重叠），
但它被淡入淡出盖住，用户看到的是「内容浮现」。

⚠️ 不要把 `.opacity()` 换成 `.animation()`，也不要删掉 alpha 状态。

## 三、测量高度的坑（必须给占位初值）

高度初值**不能是 0**：

```
高度 0  →  内层不被布局  →  onAreaChange 不触发  →  高度永远是 0  →  展开后空白
```

这是典型的循环依赖。做法是给一个**足够大的占位初值**（如 `420`），
内层因此会被布局（容器裁切到 0，用户看不见），
`onAreaChange` 量到真实高度后替换掉占位值，此后两端都是数字。

每次展开前把高度恢复成占位值，逼它重新量一次 ——
明细内容会随数据变化（多一条记录、文案变长），沿用旧高度会停在半路。

---

## 四、不要用 `transition` 做折叠

给「会因条件为假而卸载」的节点挂 `transition` 是错的：

条件转假时节点**立刻从树上移除**，`transition` 跑在一个已经不参与布局的元素上，
动画期间它还在原位置飘逸，而父容器已瞬间缩短到新高度 ——
视觉上就是**与下方控件重叠**（用户反馈过「收回时会和其他控件重叠」）。
