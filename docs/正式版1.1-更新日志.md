## 一、核心突破：折叠动画改按条数计算

### 之前为什么一直修不好

前几版都在想办法**测量**内容高度，而在这套结构下**根本测不到**：

> `onAreaChange` / `onSizeChange` 报的是**容器被赋予的尺寸**，
> 不是内容的自然尺寸。只要外层限定了高度（0 或占位值），
> 就永远拿不到真实值。

试过并失败的六条路（详见 [展开动画3.0.md](展开动画3.0.md)）：

| 尝试 | 结果 |
|---|---|
| 明细常挂 + `height(0)` + clip | 内层被压成 0，恒报 0 → 展开空白 |
| `visibility(Visibility.Hidden)` | 隐藏节点不参与布局，量不到 |
| `opacity(0)` | 同样量不到 |
| 收起态不裁切 | 内容漏出卡片，测量归属也不可靠 |
| 展开时才挂载后立刻量 | 能显示，但第一次必然「先占位 → 量到 → 撑开」地闪 |
| 高度存父页面、组件回传 | 仍依赖测量，第一次照样闪 |

### 现在的做法

每条记录卡片（`RecordRow`）结构固定 ⇒ 单条高度是**常量** ⇒ 直接算：

```
明细高度 = 上下内边距 + 条数 × 单条高度 + (条数-1) × 间距
```

高度在**渲染之前**就已确定，不存在测量这一步，所以第一次展开就是正确长度。
记录增删、换日期都只影响条数，高度自动跟着变 —— 不需要任何缓存或失效逻辑。

### 代价

`RECORD_ROW_H (82)` / `DETAIL_PAD_V (12)` / `DETAIL_GAP (8)` / `EMPTY_HINT_H (46)`
必须与 `RecordRow.ets` 和 `mealDetail` 的实际尺寸**联动**。
改字体/内边距/行数时要同步改常量，否则展开高度会对不上（小了被裁、大了留白）。

## 二、本版包含的其他改动

### 首页

- **餐次改卡片层级**：每餐一张白色卡片（圆角 + 阴影），
  标题行与明细之间加分隔线 —— 原来四餐是一段裸列表，糊成一片分不清边界
- **收起态摘要**：有记录列菜名 + 千卡；无记录显示「还没有记录 / 0 千卡」
  （原来无记录的餐次收起后一片空白）
- **展开/收起动效**：高度即时变化 + 透明度淡入淡出
- **修掉启动闪退**：`MealFold` 误用 `@Link` 绑定方法返回值
  （`@Link` 要求父组件用 `$` 绑定状态变量，传表达式会运行期抛异常，编译期不报错）

### 我的

- **个人情况卡片支持折叠**（展开动画 1.0），收起时给一行摘要：
  `男 · 20 岁 · 188 厘米 · 110 公斤 · 轻度活动 · 快速减脂`
- 拾色器补齐三档文字样式 + 「上下滑动选择」提示
- 全部输入框显式设置 `fontColor` / `placeholderColor`（系统默认色在浅色底上读不出）
- 体重趋势的「记录」按钮由胶囊改为矩形（与左侧圆角输入框成一组）

### 记录

- 体重记录实时刷新（`refreshTick` 补 `@Watch`；`WeightChart` 补 `refreshKey`）
- 日历翻到非本月、点进去返回后**停在原月份**（原来被拉回本月）
- 「补记」按钮背景不再紧贴文字

### 二级页

- `Camera` / `ResultConfirm` / `ManualAdd` / `AiSettings` 四页顶部安全距离
  统一为 `AppState.topInset + 8`（原来只留 8vp，顶栏会压在系统时间上）
- 拍照识别确认记录后**回首页**（原来退回拍照页）：
  拍照页跳确认页由 `pushUrl` 改为 `replaceUrl`，页面栈变成
  `[Index, ResultConfirm]`，一次普通 `back()` 就落到首页

### 桌面卡片（2x2）

骨架已完成，**界面尚未真机验证**：

- 布局：左热量环 + 右三大营养素条 + 下方「拍照记录」按钮
- 点「拍照记录」→ 直接进应用拍照识别；点其它位置 → 进首页
- 数据由 `CalorieCardAbility` 通过 `formBindingData` 传给卡片，
  卡片用 `@LocalStorageProp` 按同名键读取（SDK 文档确认的机制）

卡片环境有两条硬限制（踩过）：
- **不支持 `animateTo` 与 `getUIContext`**，编译期即报错 —— 卡片里做不了动效
- `form_config.json` **不允许注释**，加了会报 `Failed to parse the JSON`
