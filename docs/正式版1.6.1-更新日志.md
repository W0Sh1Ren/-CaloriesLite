## 修掉的三个致命问题

### 一、`isDynamic: false` —— 卡片收不到任何数据

`form_config.json` 里原来是 `"isDynamic": false`。静态卡片**收不到
`formProvider.updateForm` 的推送**，永远停在初始数据。

这解释了为什么这张卡片一直没验证通过：它根本没在更新。

### 二、卡片 UI 里做派生计算 —— 读不到值

卡片跑在系统卡片框架进程里，它的响应式追踪**不追踪 getter /
辅助方法内部对 `@LocalStorageProp` 的依赖**。原来的卡片里全是这类写法：

```ts
this.macroBar('蛋白', this.protein, this.proteinTarget)  // 方法内读属性
private isEmptyDay(): boolean { … }                      // 方法内读属性
CalorieCard.ratio(now, target)                           // 静态方法算
```

现在改成**零派生**：新增 `widget/CardData.ets` 作为统一数据契约，
所有派生（百分比、文案、配色、空状态判断）都在那里算好，
卡片只负责把字符串贴到界面上。

### 三、卡片里用 `FormLink` —— 点了没反应

`FormLink({ action: 'router', … })` 在桌面卡片里**点击无效**（实测）。
换成卡片实战文档给的写法：

```ts
postCardAction(this, { action: 'router', abilityName: 'EntryAbility' })
```

`postCardAction` 是卡片专用的全局函数，**不能用普通 `.onClick` 跑业务逻辑**。

另外两个同类约束也一并遵守了：

- **不用 `Button` 组件**：卡片里 `Button` 的带参构造不渲染文字
  （只剩背景色几个白点），可点击元素一律用
  `Text` / `Row` + `backgroundColor` + `borderRadius` 模拟
- **`postCardAction` 不能链在 `@Builder` 调用后面**（返回 void），
  要包一层容器再把事件绑在容器上

## 新增能力

### 三处配置/逻辑补齐

| 位置 | 内容 |
|---|---|
| `CardData.ets` | 新增，卡片统一数据契约，Ability 与卡片共用 |
| `CalorieCardAbility.onFormEvent` | 处理卡片「刷新」按钮的 `message` 事件，防御式解析 `params.action` |
| `Index.consumeCardRoute` | 从卡片进拍照页前，把目标日期设为**今天**、餐次按时间猜 |

### 顺带修掉一个真 bug

`consumeCardRoute` 原来没设 `AppState.targetDay`，会**沿用记录页残留的日期**：
用户刚在记录页翻到 10 月 3 日补记过，再从桌面卡片点「拍照记录」，
记录会落到 10 月 3 日而不是今天。

### 记完一笔，卡片立刻更新

- **立刻**：`Index.reload()` 里调 `AppState.refreshCard()` →
  `formProvider.reloadAllForms()`。挂在 reload 上是因为它是当日数据变更的
  唯一汇聚点（拍照确认 / 补记 / 删除 / 运动 / 体重五个入口全覆盖）
- **兜底**：`updateDuration: 1`（系统每 30 分钟刷一次）

用 `reloadAllForms` 而不是 `updateForm`：后者需要 `formId`，而 `formId`
只在 `onAddForm` 时拿得到、主应用进程与之不共享内存
（跨进程共享要落盘，见卡片实战文档第 9 节）。

### 右上角刷新时间

`CardData.nowText()` 在**后端**格式化成 `"14:36 更新"` 再推过来 ——
卡片侧 `new Date()` 取时间属于派生，会读不到值。

## 布局调整

- 环与营养素靠左：卡片左内边距 `12 → 8`，左列容器 `84 → 68`，
  环本体 `72 → 60`（后两个必须一起改，否则环被裁）
- 底部按钮换位：**左「拍照记录」（宽）｜右「刷新」（窄）**，
  主操作在左更显眼、次要操作用浅灰底不抢视觉重量

`CalorieCard.ets` 文件头有完整的**布局速查表**（ASCII 图 + 属性对照 +
改完怎么生效），改布局只需看那一节。

## 一个未做的功能

用户希望「点刷新时，环与营养素从 0 动画到当前值，复用首页动画」。

**当前未实现**，原因是硬约束：卡片环境**不支持 `animateTo` 与
`getUIContext`**（编译期就报 `'animateTo' can't support form application`），
所以首页那套 `animateTo` 插值动画无法直接复用。

可行的替代路径是把卡片内的值从 `@LocalStorageProp` 拷进 `@State`，
再用定时器逐帧改 `@State` —— 但这**违反了本文件头约束 3**
（卡片 UI 不维护自己的状态），且卡片进程的后台时长受限、
首帧闪烁风险未知，需要真机验证。

## 验证

真机确认：

- 卡片显示正常（环、三条营养素、刷新时间、按钮）
- 点「刷新」→ 卡片进程收到 `onFormEvent: {"action":"refresh","params":{"action":"refresh"}}`
- 点「拍照记录」→ 直接进拍照页，且记到今天
- 应用里记完一笔 → 日志显示 `reloadAllForms -> 1`，卡片进程读到新数据

⚠️ 布局改动**不会热更到已添加的卡片**，改完要先删掉桌面卡片再重新添加。
