## 修复

### 菜越多，餐次卡片底部空白越厚

**现象**：展开某一餐后，最后一张食物卡片下方留出大片空白；
菜品越多，空白越厚（4 条时已明显）。

**原因**：`RECORD_ROW_H`（单条记录卡片高度）是**估算**的，不是实测的。

我按字体行高相加：

```
内边距 10+10  +  16sp行高约22  +  12sp行高约17  +  11sp行高约15
              +  两个 3 的间距  =  80
```

再「+2 作为卡片阴影的呼吸」→ **82**。但：

1. **ArkUI 的实际行高系数与字体度量不是这样简单相加**，每条实际只有 71.7vp；
2. **`.shadow()` 根本不占布局空间**，那 2vp 纯属多余。

于是每条多算约 10vp，而这个偏差**会被乘以条数**：

```
6 条 × 约 8vp ≈ 50vp 的空白
```

**修复**：改用真机实测值。

```
真机 dump 边界（density 3.5）：
  6 条午餐记录 → 每张卡片 251px = 71.7vp，六张完全一致
⇒ RECORD_ROW_H = 72
```

修复后 6 条记录的卡片底部空白消失。

## 教训

**凡是「按 UI 结构推算出来的尺寸」，都要用真机实测校验一次。**

我先前还围绕这个常量写了一段自认为严谨的推导（含行高、间距、
甚至阴影呼吸），看起来很合理，但差了一条卡片的高度。
这类错误在单条时不明显，**乘以数量后才暴露** —— 所以更要实测，
而不是相信推导。

已把这段经历写进 [展开动画3.0.md](展开动画3.0.md) 第三节，
连同实测方法（不裁切容器 + `onAreaChange`，或 `dumpLayout` 读 bounds）。
